# Memory Decay Library v1 Implementation Plan

> **For Hermes:** Execute in vertical, test-first slices. For every new behavior, record the expected RED test failure before adding production code; run focused and full suites after GREEN.

**Goal:** Publish a fully local, composable memory-decay library with a Go engine, fixed-width primitive C ABI, installable Python wrapper plus pure-Python reference, JSONL sweep adapter, and native GitHub Actions builds for Linux/macOS/Windows x86_64/arm64.

**Architecture:** The Go module owns deterministic score math and the batch sweep. A deliberately narrow `c-shared` ABI accepts only `int64` and `float64` and returns scalar values/statuses, so Python can call it in process via `ctypes` without allocating or owning Go memory. The Python distribution bundles one platform-native library and exposes the same score semantics as its readable pure-Python oracle. A JSONL adapter proves the complete pruning workflow without making any database dependency part of v1.

**Tech stack:** Go (cgo/c-shared), Python 3.9+ / `ctypes`, `pytest`, `uv`, standard-library JSONL, GitHub Actions native OS runners, `cibuildwheel` subject to packaging research confirmation.

## Product contract to lock before code

### Scope
- Two deterministic models in v1: exponential and importance-weighted power-law.
- Input timestamps are Unix epoch seconds (`int64`, UTC); elapsed time is clamped at zero for a future access time.
- Score output is finite and normalized to `[0.0, 1.0]`; `1.0` means fully retained and `0.0` means fully decayed.
- Importance is finite and constrained to `[0.0, 1.0]`; invalid parameters are rejected rather than silently coerced.
- `threshold` means **prune when `score < threshold`**. Equality is retained to make behavior stable at the boundary.
- JSONL sweep supports `--dry-run`, then explicit `--mode archive|delete`; all decisions are auditable through structured JSON logs.
- v1 has no network service, no LLM, no API key, no embeddings, and no database-specific dependency.

### C ABI invariants
- Only fixed-width primitives cross the boundary: `int64_t`, `double`, and `int32_t` status/model values.
- No Go pointer, Go string, C string, struct, callback, or caller-owned buffer crosses the boundary in v1.
- ABI functions return status codes and write scalar output through an explicit `double*` out parameter.
- Invalid arguments never panic across the FFI boundary.

## Tasks

### Task 1: Bootstrap and executable specification

**Objective:** Establish reproducible Go/Python tooling, public conventions, and a maintained later-work backlog before production code.

**Files:**
- Create: `go.mod`, `python/pyproject.toml`, `docs/backlog.md`, `README.md`, `.gitignore`
- Create: `pkg/decay/score_test.go`, `python/tests/test_reference.py`

**Steps:**
1. Install a supported Go toolchain locally and verify `go version`, `go env CGO_ENABLED`, and C compiler discovery.
2. Write one failing Go and one failing Python reference test for each first score-model behavior.
3. Record observed RED failures.
4. Add minimal project metadata and test commands.
5. Commit bootstrap only after both suites are runnable.

### Task 2: Exponential score vertical slice

**Objective:** Implement and prove the basic score formula in Go and the pure-Python oracle.

**Files:**
- Create: `pkg/decay/exponential.go`
- Modify: `pkg/decay/score_test.go`, `python/src/decay_library/reference.py`, `python/tests/test_reference.py`

**Steps:**
1. Add a failing boundary/known-value Go test.
2. Run it and confirm it fails because the model is absent.
3. Implement the smallest validated formula and argument errors.
4. Add the corresponding pure-Python oracle behavior.
5. Run focused tests, full Go tests, and full Python tests.

### Task 3: Importance-weighted power-law slice

**Objective:** Add the second model with explicit, documented importance semantics and parity tests.

**Files:**
- Create: `pkg/decay/powerlaw.go`
- Modify: score and Python reference tests

**Steps:** Follow a separate RED → GREEN → REFACTOR cycle for: zero elapsed time, importance ordering, long elapsed time, invalid arguments, and Go/Python numerical parity.

### Task 4: Native ABI and local ctypes user journey

**Objective:** Export score calls safely as a platform native shared library and demonstrate `ctypes` in a separate process.

**Files:**
- Create: `native/exports.go`, `native/exports_test.go`
- Create: `python/src/decay_library/native.py`, `python/tests/test_native.py`
- Create: `scripts/build-native.*`, `scripts/test-clean-install.*`

**Steps:**
1. Write a Python integration test that expects an installable native wrapper but fails before its implementation/build artifact exists.
2. Build the Windows DLL with `go build -buildmode=c-shared` and inspect its generated header.
3. Implement only scalar ABI functions and Python argument/status translation.
4. Create a clean venv, install the package as a user would, import it, and compare native/reference results.
5. Exercise malformed inputs and verify controlled Python exceptions, not process crashes.

### Task 5: JSONL sweep adapter and CLI

**Objective:** Run a real archive/delete decision process against a store-like JSONL file, safely and audibly.

**Files:**
- Create: `internal/jsonl/store.go`, `internal/sweep/sweep.go`, `cmd/decay-sweep/main.go`
- Create: tests and fixtures under `internal/.../*_test.go`, `tests/fixtures/`

**Steps:**
1. Write a failing test for dry-run decision counts and threshold equality.
2. Implement streaming JSONL scan and deterministic output ordering.
3. Add archive/delete behavior with write-to-temp plus atomic replace safeguards.
4. Emit one structured JSON log object per run and optional decision records.
5. Run a realistic thousands-record synthetic store manually; preserve real command output in verification evidence.

### Task 6: Pythonic adapter protocol and complete local pipeline

**Objective:** Provide `decay.score(...)` and `decay.prune(store_adapter, threshold)` without tying Python to a specific database.

**Files:**
- Create: `python/src/decay_library/__init__.py`, `api.py`, `adapters.py`
- Create: Python tests for protocol and JSONL integration

**Steps:** Test first against a small in-memory adapter and the JSONL reference adapter; ensure callback/object work stays in Python rather than the cgo boundary.

### Task 7: Packaging and native platform matrix

**Objective:** Build distributable wheels and sweep artifacts natively for every claimed target.

**Files:**
- Create: `.github/workflows/ci.yml`, `.github/workflows/release.yml`, `scripts/package-*`
- Modify: `python/pyproject.toml`, README

**Steps:**
1. Select packaging tooling using current maintenance evidence, preferring a transparent native runner build over an opaque unsupported extension helper.
2. Build on GitHub-hosted native OS runners for Linux, macOS, Windows; include x86_64 and arm64 where runner availability supports it.
3. On each target, create a fresh venv, install the built wheel, run import/native/reference parity tests, and run the CLI artifact.
4. Upload testable artifacts and retain their names/URLs in verification records.
5. Do not claim a target is supported until its actual run is green.

### Task 8: Documentation, realistic verification, and review loop

**Objective:** Deliver evidence, audit every requirement, and iterate on all findings.

**Files:**
- Modify: README, `docs/backlog.md`
- Create: `docs/verification.md`

**Steps:**
1. Provide inline Python RAG scoring, scheduled CLI sweep, and Go-native examples.
2. Generate several thousand deterministic synthetic records spanning both models and importance values.
3. Record before/after counts, representative individual pruning reasons, structured log output, and clean-install commands/output.
4. Perform a reviewer pass on `git diff`: ABI types, no Go/C allocation transfer, cgo build assumptions, error handling, resource closure, argument validation, CI claims, and docs accuracy.
5. Turn all non-v1 ideas/found issues into explicit backlog entries before final reporting.

## Verification gates
- No task is complete from compilation alone.
- Every added behavior has an observed failing test followed by a passing focused test and regression run.
- The Python wrapper is tested from a clean venv via actual `pip/uv` install and a standalone user script.
- The CLI is run on a realistic synthetic JSONL store and produces inspectable audit logs.
- Every published OS/architecture has a successful native build, install/import, API parity, and CLI run in CI.
- The final report includes concrete command output/artifact paths, failures/deviations, and publication confidence.
